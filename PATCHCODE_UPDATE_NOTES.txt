Patchcode update notes
======================

Current package name: patchcode
Main tools: patchcode, diffcode
Current section separator: <@+@+@>

Recent changes
--------------

1. Added directory comparison mode to diffcode.

   Usage:

       diffcode dir1 dir2 outputpatchcodepatchfile.patch

   This recursively compares regular files under dir1 and dir2 and generates a
   single patchcode patch file containing patch sections for each changed path.

2. Directory-mode patch target behavior.

   By default, generated filename headers target the original directory root:

       filename:dir1/relative/path.txt

   To generate patches for a different working copy or target root, use:

       diffcode --target-root workdir dir1 dir2 changes.patch

3. Directory-mode file categories.

   - Files present in both directories are emitted as normal patch hunks.
   - Files present only in the updated directory are emitted as full-file
     creation segments.
   - Files present only in the original directory are emitted as empty full-file
     replacement segments for review. The current patchcode format does not
     physically delete files.

4. Added missing-parent-directory creation to patchcode rewrite handling.

   This allows patches generated for added files in new subdirectories to be
   applied without manually creating all parent folders first.

5. Added safety checks in diffcode.

   - Single-file mode rejects files containing NUL bytes.
   - Directory mode skips files containing NUL bytes.
   - diffcode skips files that contain a line exactly equal to <@+@+@>, because
     that line cannot be represented safely inside the current separator-based
     patch file format.

6. Updated tests.

   tests/run_diffcode_tests.sh now covers:

   - middle-of-file changes
   - beginning-of-file changes
   - end-of-file changes
   - full-file replacement
   - insert-only hunks
   - directory mode changed files
   - directory mode added files in nested directories
   - directory mode deleted-file review segments
   - default directory target-root filename generation
