Patchcode update notes
======================

Changes made in this package:

1. Renamed the project to patchcode.
   - Executable target: patchcode
   - CMake project: patchcode
   - Source/header files: patchcode_*.cpp / patchcode_*.h
   - User-facing help text and README now use Patchcode/patchcode.

2. Replaced the old patch section separator with '<@+@+@>'.
   - Patch files now use a line containing exactly <@+@+@> between:
     * start code location
     * updated code
     * end code location
   - Ordinary at-sign characters in patch payload lines are no longer interpreted as separators.

3. Parser fixes.
   - Replaced fragile character-by-character parsing with line-preserving parsing.
   - Preserves CR/LF in patch payload lines.
   - Handles EOF and incomplete segments more safely.
   - Ignores metadata comments and blank lines cleanly.

4. Patch application fixes.
   - Fixed out-of-range iterator and dereference bugs in code-location matching.
   - Fixed insertion at end-of-file.
   - Fixed deletion range clamping.
   - Initialized code-line state consistently.
   - Avoids rewriting files when a patch segment fails to apply.
   - Handles missing source files more safely.
   - Uses binary mode for source reads/writes/backups to preserve line endings.

5. Build fixes.
   - CMake now sets C++11 explicitly.
   - Build verified with cmake and GNU C++ in this environment.

Verification performed:

    cmake -S . -B build
    cmake --build build -j2

Diffcode generator update
=========================

Additional changes made in this package:

1. Added a second command-line executable: diffcode.
   - Usage: diffcode [options] <original-file> <updated-file> [output.patch]
   - It compares two text files and emits a patchcode patch file.
   - Generated patches use the current '<@+@+@>' separator.

2. Generated patch metadata.
   - diffcode writes filename, author, patchname, timestamp, enable, bugs, and extra headers.
   - Defaults are intentionally fillable placeholders for author, patchname, and bugs.
   - Options are available to set these fields during generation.

3. Generated pattern matching.
   - diffcode creates start and end code-location pattern sections around each changed hunk.
   - The default minimum anchor size is 3 lines.
   - Anchors expand up to 8 lines by default to reduce duplicate pattern matches.
   - Small or whole-file changes fall back to the patchcode full-file replacement marker.

4. Verification performed for this update:

    cmake -S . -B build
    cmake --build build -j2
    diffcode-generated patch applied with patchcode and compared successfully against updated files.
